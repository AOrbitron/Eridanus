# 森空岛服务

## 游戏信息

- 明日方舟信息卡：`我的明日方舟`、`我的方舟`、`我的方舟z`、`明日方舟信息`、`明日方舟便签`、`方舟便签`。替换原来的 `我的森空岛`、`森空岛信息`、`森空岛info`、`sklandinfo` 入口。
- 终末地信息卡：`终末地信息`、`我的终末地`、`终末地便笺`。同一张卡的“每日信息”区域整合 BeyondUID 每日查询的体力、每日活跃、周常、通行证、签到状态，并显示回满时间、接口数据时间（北京时间）及轮换活动项。多个入口均实时请求、重新绘图。
- 两个入口均支持 @ 已绑定的用户，使用通用配置中的 HTTP 代理。信息查询实时请求，不依赖抽卡缓存；没有绑定相应游戏时给出重新登录绑定提示。

信息查询位于 `skland.py` 的 `skland_info`、`endfield_info`；`core/api/request.py` 的 `endfield_card` 使用 BeyondUID 同款 `/api/v1/game/endfield/statistic`，采用网页签名和明确的 `sk-game-role: 3_<roleid>_<serverid>`。`core/schemas/endfield_card.py` 兼容旧统计字段及新版 `items`，未公开的数据不会显示为零；`core/render.py` 的 `render_endfield_card` 沿用明日方舟卡片的绘图风格。凭据过期复用现有自动刷新机制，HTTP 401 也进入刷新流程。

## 干员、模组与武器基质

触发形式为 `明日方舟/方舟 + 干员/模组 + 图鉴/攻略 + 干员名`，以及 `终末地 + 武器 + 图鉴/攻略 + 武器名`，无需绑定森空岛账号。

| 功能 | 指令示例 | 内容 |
| --- | --- | --- |
| 干员图鉴/攻略 | `明日方舟干员图鉴能天使`、`方舟干员攻略能天使` | 职业、星级、特性、最高精英基础属性、天赋、潜能、信赖、最高等级技能 |
| 模组图鉴/攻略 | `明日方舟模组图鉴能天使`、`方舟模组攻略能天使` | 全部已配置模组、各等级属性及效果、潜能差异；长内容自动分张 |
| 武器图鉴/攻略 | `终末地武器图鉴落草`、`终末地武器攻略落草 不知归` | 单武器最佳基质副本、多武器共刷及预刻写词条、完整/部分共锁、顺带可刷武器 |
| 资源更新 | `明日方舟更新资源`、`终末地更新资源` | 按游戏更新查询所需的静态游戏表，全部下载并通过校验后整体替换；失败保留旧版 |

`图鉴` 和 `攻略` 对应相同功能，也支持类别与查询词之间加空格，例如 `方舟 干员 攻略 能天使`；保留名称前置写法，例如 `终末地落草 不知归武器攻略`。也支持既有游戏别名（如 `ark`、`endfield`）。原 `武器基质`、`武器基质副本`、`武器刷什么基质` 入口已改为 `武器图鉴`/`武器攻略`。多个武器以空格、逗号或顿号分隔，每次最多 8 把；含空格的英文全名可用英文双引号包裹。部分名称未找到时，照常绘制识别成功的武器，并在图中列出未识别名称。同名干员提示使用对应 ID 区分，不猜测形态。

首次查询会自动下载所需游戏表。静态表位于本服务 `data/guides/<game>/tables.json`，游戏原始头像复用 `data/gacha/<game>/assets/`；不保存图鉴或基质成品图索引。全部新图片直接输出到项目根 `data/pictures/cache/`，每次重新绘图，页脚为 `function by manshuo`。基质绘图保留 BeyondUID 原有深色金色方案卡与武器/角色图标；头像不可用时使用占位，下次查询补充。

入口为 `command/guide.py`，数据与绘图位于 `utils/arknights_wiki.py`、`utils/draw_wiki.py`、`utils/endfield_gamedata/`、`utils/draw_gem.py`，下载位于 `utils/guide_resource.py`。代码来源、许可和原始表结构差异见 [GUIDE_SOURCES.md](utils/GUIDE_SOURCES.md)。

## 抽卡记录

国服明日方舟、明日方舟：终末地的真实寻访记录，复用现有“森空岛登录”保存的鹰角凭据及角色绑定，不需要手动提供链接或 token。

| 操作 | 明日方舟 | 终末地 |
| --- | --- | --- |
| 查询统计图 | `明日方舟抽卡记录` | `终末地抽卡记录` |
| 增量更新 | `明日方舟更新抽卡记录` | `终末地更新抽卡记录` |
| 全量更新 | `明日方舟全量更新抽卡记录` | `终末地全量更新抽卡记录` |

也支持“查看抽卡记录”“刷新抽卡记录”“全量刷新抽卡记录”。游戏别名分别包括 `方舟 / ark / arknights / mrfz`、`明日方舟：终末地 / endfield / byd / zmd`。群消息可以 @ 已绑定森空岛的用户查询或更新其记录，与米游社入口一致。

查询默认读取本地原始记录；第一次查询自动遍历所有分类并保存，包括有效的空结果。普通更新逐分类查询到已保存记录即停止；全量更新继续翻页至接口无更多数据，并在写入前保存 `.json.bak` 备份。两种更新都合并已有历史，官方接口已不再返回的旧记录不会被删除。全量更新只能补充接口仍能返回的记录。更新消息仅把真正新增的抽取计入“新增 N 抽”，附加奖励另外计数。

**终末地记录查询有 90 日范围，不等于账号终身历史。** [官方版本说明](https://endfield.hypergryph.com/news/9335) 说明了寻访与申领记录的查询范围。BeyondUID 也依赖持续保存的 `gacha_logs.json` 保留更早记录；首次接入时无法从当前接口恢复已过期且未存档的明细。图中使用“已记录”而非累计抽数，并显示范围提示。`streams[*].complete` 仅表示已完成接口当前可返回范围的遍历，`coverage.account_history_complete=false` 明确不保证账号终身完整。

终末地请求特许、复刻、基础、新手、联合及元数据发现的其他角色池类型；武器按池查询，包含已经下线的池，同时始终查询不带 `pool_id` 的汇总接口并去重，避免池目录缺少历史池导致遗漏。记录原字段完整保存，赠礼不算抽数；免费抽单独计数，不推进普通抽数统计。某一分类失败会保留该分类的旧数据并提示，全部失败或超时不覆盖已有文件。

数据目录相对于本服务：

```text
data/gacha/
├── arknights/
│   ├── players/<游戏 UID>_1.json
│   └── assets/                       # 干员头像，按需下载并复用
└── endfield/
    ├── players/<游戏角色 UID>_1.json  # 使用 roleid，而非换授权的账号 uid
    └── assets/                       # 角色、武器头像，按需下载并复用
```

原始记录不保存登录 token，登录凭据仍位于原有数据库 `users.user_data.skland.user_info`。授权时终末地使用账号侧 `uid` 换 U8 token，显示和保存记录使用 `roleid`，不能混用。

信息图和抽卡图均直接写入 Eridanus 的 **`data/pictures/cache/`**，不建立账号或功能子文件夹。每次发送均重新执行绘图并生成新文件名；不读取旧成品图，也不保存成品图索引。抽卡原始历史与可复用的游戏素材分开保存，以保留官网过期后的历史。

抽卡图底部署名为 `function by manshuo`。两个游戏均提示“官方仅提供最近90天记录，图中包含已存档历史，不代表账号累计抽数。”

入口为 `run/anime_game_service/skland.py`，指令位于 `command/card.py`，授权和存储位于 `utils/gacha.py`，统计和 Pillow 绘图位于 `utils/draw_gacha.py`。HTTP 请求及头像下载使用 `config.common_config.basic_config['proxy']['http_proxy']`；头像下载失败时使用名称占位，下次查询补下载。绘图展示总抽数、六星、免费次数、附加奖励及各分类的六星获取间隔、已记录平均值和垫抽，最新记录在前。抽卡结果较多时，按卡池面板向右增加列，每列保持 1200 像素宽并在约 2100 像素正文高度后续列；整份记录合成同一张图片发送，不再拆成多张。

抽卡图参照 BeyondUID：每列 1200 像素宽，使用游戏标题背景、黄色统计卡、灰色斜切池头、六列橙色六星卡片和 UP 标记。头图、账号头像、标题、总览统计和“记录范围：自 YYYY.MM.DD 起”仅在第一列显示，第二列起直接从顶部排列寻访记录；各池另列自身的日期范围。记录起始日期取全部已保存抽取明细中最早的时间（北京时间）。终末地武库显示在同一个区块，但仍按各武器池独立计算间隔；只对游戏表中明确存在的 UP 标注，不猜测不歪率。明日方舟使用自身游戏背景，不使用终末地标题。素材来源见 [GACHA_ASSETS.md](core/resources/images/GACHA_ASSETS.md)。

BeyondUID 的真实记录协议可用作参考；ArknightsUID 的 `arknightsuid_gacha` 是模拟寻访，因此明日方舟真实记录额外参考现行官网角色认证、分类及时间戳和位置双游标接口，详见 `utils/gacha.py` 的来源说明。
